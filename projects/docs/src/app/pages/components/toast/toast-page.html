Toast

A toast is a short message that appears at the edge of the screen and goes away by itself. Inject CkToast from @ckui/core/toast and call show(): it adds one container to the page on first use, announces each message to screen readers, stacks a few at a time and queues the rest. Use it for confirmations and passing status, not for anything the user has to answer.

Examples

Tones

There are four tones. Each has its own icon, so the tone never rests on colour alone. Danger is a filled card, stays until it is dismissed and is announced assertively; the other tones are polite and close after five seconds.

Action

An action adds a button. Using it calls run() and closes the toast with the reason action. A toast with an action does not close by itself, because a timer would take the choice away from slow readers; give it a duration to change that.

Queue

Three toasts show at once. Later ones wait, are announced when they appear and start their timer then. dismissAll() closes the visible and the waiting ones. 

{{ samples.queue }}

Long content

Text wraps, also an unbroken word. Past 30% of the screen height the text scrolls inside the card, so the buttons stay on the screen. Keep messages short.

Position and size

provideCkToast() sets the edge, the alignment, how many show at once and the size of the buttons for the whole app. Nothing else needs configuring. The stack always puts the newest toast nearest the edge, respects the safe-area insets of a phone and, on a narrow screen, spans the width minus a 1rem gutter. Under xl the action and the dismiss button are 60px high.

Why a toast closed

ref.dismissed resolves once with the reason. The first reason wins: a toast that was replaced never reports a later timeout.

On the server show() does nothing: no container, no announcement, and dismissed resolves as programmatic at once. When the app is destroyed every toast closes the same way and the container is removed.

Keyboard

A toast is not a dialog and follows no keyboard pattern of its own: its buttons are ordinary buttons. It never takes focus.

Accessibility

  • Each toast is announced once to screen readers through a live region: assertively for danger, politely for the rest, as the title followed by the message. Changed text is announced again; a replacement with identical text at the same urgency is not. Toasts shown in the same moment are spoken together, in order, and assertively if one of them is. A queued toast is announced when it appears. Nothing is announced on the server or for the container itself.
  • The container is a section named by the notifications label, which can be translated through provideCkui({ labels }). The dismiss button is named by the dismiss label.
  • Timing follows WCAG 2.2.1. A toast with an action, and every danger toast, stays until it is dismissed unless you set a duration. The timer pauses while the pointer is over the toast, while focus is inside it and while the page is hidden, and then continues with the time left, at least one second. A toast that was shown while the page was hidden starts its timer when the page is visible.
  • Swiping a toast sideways dismisses it past a third of its width, or on a quick flick. A drag that ends short springs back, and a mostly vertical drag is left to scroll the page. The swipe is only a shortcut: every toast has a dismiss button, which is at least 44px on a touch screen.
  • The container is exempt from inert and painted above dialogs, so a toast stays readable and its buttons clickable while a dialog is open. The tab key still stays inside a modal dialog.
  • Tones differ by icon as well as colour. Text meets 4.5:1 in every tone and theme, the tone icon 3:1 against its card. On a danger card the action and dismiss buttons take the text colour and hover in the danger shades.
  • In forced-colors mode every toast has a visible border. With reduced motion the toast neither slides in nor out, and a drag still follows the finger.
  • The toasts are the last thing in the document, so the keyboard reaches them after the page. A toast that holds focus when it closes hands focus on first: to the same button of the next toast (else the previous one), else back to the element that had focus before it entered the toasts, else, with a modal dialog open, into the dialog. Focus is never dropped to the page.
  • Global element styles. A global rule such as button:focus-visible { outline: … } beats the layered buttons of the toast, and a reset such as section { … } reaches the container. Declare resets in a layer before ckui, or scope them with :not(.ck-button).
  • Under a nested data-ck-theme the container, being a child of body, follows the theme of the page, not of the section that called show().
