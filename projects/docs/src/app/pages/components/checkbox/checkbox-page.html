Checkbox

ck-checkbox is one yes or no choice that is saved with a form: accept the terms, save as template. ck-checkbox-group turns several of them into one array value. A checkbox is a native <input type="checkbox"> under a label, so the whole row is the tap target. Both work with Reactive Forms, ngModel and Signal Forms. Import CK_CHECKBOX_IMPORTS (the checkbox, the group, ck-hint and ck-error) from @ckui/core/checkbox. For a setting that applies the moment it is flipped, a switch says that better.

Examples

Basics

The value is a boolean and works two-way with [(value)]. The text inside ck-checkbox is the label: it names the checkbox, and a click anywhere on the row toggles it. ck-hint adds a line of help; it describes the checkbox (a screen reader reads it after the name) and is part of the row, so a click on it toggles too.

Accept the terms

A checkbox that must be ticked holds a ck-error. It stays hidden until the control is invalid and touched (focus has left it), or its form was submitted. While it shows, the input is aria-invalid and the error is part of its description, so it is announced when the checkbox is focused. The validator is yours: Validators.requiredTrue here.

A group with an array value

ck-checkbox-group holds the array of the options that are checked. Each checkbox in it takes an option instead of a value. The array keeps the order of the checkboxes in the page, whatever order they were clicked in. The first <label> names the group (it has role="group"). The group shows the error, once, below the list: focus moving between its checkboxes does not count as touched, leaving the whole group does, and every checkbox is aria-invalid while it shows.

required on the group only draws the marker on the label; a group is not allowed aria-required, and it never validates by itself. Your form does. Validators.required fails an empty array, but Validators.minLength(1) does not (Angular skips empty values), so use the first. The required attribute next to formControl or ngModel adds Validators.required too. In Signal Forms use required() or minLength(path, 1). A value in the array that no checkbox has as its option is kept, at the end, and development builds warn. Hint and error must be direct children of the group, and so must the checkboxes for the gap between rows.

One control, three form APIs

The same controls three times. A programmatic write (setValue, a model change, reset) moves the box and never counts as a change by the user; only a click or Space does. null from a form counts as unchecked, and as an empty array for a group. A checkbox is touched when focus leaves it, a group when focus leaves the whole group.

Sizes

The size follows provideCkui() unless you set it. The box grows from 1.125rem to 1.5rem, and the row is never lower than the control height of its size, so it is 44px or more on a coarse pointer and 60px at xl. A group's size is the default for its checkboxes; a checkbox can still set its own.

Disabled

A disabled checkbox is blocked, greyed and skipped by Tab, and it keeps showing its state by the tick or the dash. A disabled group disables every checkbox in it, and a <fieldset disabled> around checkboxes does the same without any input.

Without visible text

A checkbox with no text needs a name of its own: aria-label or aria-labelledby on ck-checkbox (they move onto the input), as for a "select this row" box in a table. Development builds warn when there is none. A group needs a name too: its <label>, or aria-label.

Accessibility

  • It follows the WAI-ARIA checkbox pattern with a native <input type="checkbox">, so the checked and mixed states are native. The text names it and a ck-hint describes it; the name does not repeat the hint. A group is a role="group" named by its label, as the pattern's grouping advice says.
  • The state is never colour alone: the box shows a tick when checked and a dash when mixed, and the border of the unchecked box is at least 3:1 from the surface, in both shipped themes.
  • Errors: while a checkbox or group shows its error, the input is aria-invalid="true" and the error is in aria-describedby, so it is read when focus arrives. A group cannot carry aria-invalid itself, so each of its checkboxes does. The error appears after the control was touched or the form submitted, never while the user is still on the first pass.
  • The row is the tap target: at least the control height of the size, so 44px or more on a coarse pointer and 60px at xl. A long label wraps in its own block, with the box next to its first line.
  • The focus ring is drawn around the box for keyboard focus only. In forced-colors mode the box border is CanvasText, a checked or mixed box is Highlight with a HighlightText mark, and a disabled one is GrayText.
  • The fill fades over --ck-duration-normal, and not at all under prefers-reduced-motion.
  • Linting. angular-eslint's label-has-associated-control flags the <label> that names a group, because it labels no control by for. Turn the rule off for templates that use ck-checkbox-group, or name the group with aria-label.
  • Global element styles. The parts are a plain label and input. An unlayered rule such as input { border: … } beats the layered control. Keep those rules off the checkbox (input:not(.ck-checkbox__input)) or put resets in a layer declared before ckui. The first rule below really breaks the checkbox; the rest scope it.
