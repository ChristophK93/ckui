Badge

ck-badge is a small status label: a pill with a short text, and optionally a leading dot or icon. It is for state such as "Connected" or "Upload failed", not for actions. It is not interactive, has no role and is not a live region. Import CK_BADGE_IMPORTS from @ckui/core/badge.

Examples

Tones

Neutral, success and warning badges sit on the control fill and colour the text. A danger badge is filled, with its own text colour on it. Every tone keeps its text at 4.5:1 or better, in both shipped themes.

Dot

dot adds a round dot before the text. It takes the text colour and is hidden from assistive technology, so the text has to carry the state.

--ck-badge-dot colours the dot on its own, for example a green dot on a neutral badge. A coloured dot is decoration: the text must still state the status, since colour alone says nothing to everyone.

Icon

Put ckBadgeIcon on an inline svg for a leading icon. It is drawn one em wide in the text colour and marked aria-hidden, so it is never read. The badge brings no icons of its own: you choose the symbol.

Sizes

md is the default, a 1.5rem pill. sm is 1.25rem and 0.75rem text for dense lists. Neither is a touch target, so they stay the same size under a coarse pointer.

Long text

A badge never wraps and never grows past its container. Text that does not fit is cut with an ellipsis while the dot and the icon keep their size. Screen readers still read the full text.

Announcing a change

A badge is not a live region. When its state changes and users must hear it, say it somewhere that is: a role="status" element, or a toast. The badge itself only shows the state.

The badge gets the classes ck-badge, ck-badge--{tone} and ck-badge--{size}. Its text lives in ck-badge__text, a block of its own, so inline markup inside the text keeps its spaces.

Keyboard

A badge is not interactive: it is not in the tab order and takes no keys. If a status should be clickable, put it in a button or a link and keep the badge inside it.

Accessibility

  • Never colour alone. The text has to state the status ("Connected", "Disconnected"). A dot or an icon is decoration: it is hidden from assistive technology, and a badge with no text at all makes development builds warn.
  • Not a live region. Changing a badge's text does not announce anything. When the change must be heard, say it yourself, in a role="status" element or a toast.
  • The badge has no role, so a screen reader reads its text in the flow of the page. Do not put an aria-label on it: an element without a role cannot be named. The text is what is read.
  • Text contrast is 4.5:1 or better in every tone, both shipped themes, against the control fill and, for danger, against the filled danger colour.
  • In forced-colors mode the badge gets a visible border and the dot is drawn in the system text colour, since backgrounds are removed there.
  • In right-to-left text the dot and the icon move to the right of the text with the rest of the content.
  • Global element styles. The badge draws its text and dot in span elements. An unlayered rule such as span { overflow: visible } (the text no longer truncates) or svg { inline-size: 100% } (the icon fills the badge) beats the layered badge. Scope such rules away from the badge or declare resets in a layer before ckui.
