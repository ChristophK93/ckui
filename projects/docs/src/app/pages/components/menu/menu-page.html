Menu

ck-menu is a list of actions behind a button, the WAI-ARIA menu button. A native <button> with [ckMenuTrigger] opens it under itself, and on a phone it becomes a bottom sheet with a Cancel row. Import CK_MENU_IMPORTS from @ckui/core/menu: it holds CkMenuTrigger, CkMenu, CkMenuItem, CkMenuItemIcon and CkMenuDivider. Items are actions only: no submenus, no checkable items and no right-click menu.

Examples

Row actions

The usual place: the end of a list row, as an icon-only button. The button needs a name, and that name also titles the sheet on a phone. The menu is the content of an <ng-template> that the button gets; each item is a native button with its own (click). A [ckMenuItemIcon] leads an item, tone="danger" marks the destructive one and ck-menu-divider sets it apart.

A disabled item

A disabled item is dimmed and read as dimmed, and the arrow keys still stop on it, so a keyboard or screen reader user finds out that the action exists. Enter, Space and a click do nothing, and the menu stays open. Use the disabled input, never the native attribute.

An item that opens a dialog

Activating an item closes the menu first and then runs your (click). A handler that opens a CkDialog therefore opens it on a page without a menu, and when the dialog closes focus goes back to the button that opened the menu.

On a phone

When the menu opens on a narrow viewport with a coarse pointer (the viewport is read at that moment), it is a bottom sheet instead of a popover: a dialog named after the button, with the name as its visible title, then the items as full-width rows of at least 44px, then a gap and a divider and a Cancel row. Cancel is a plain button after the menu, not an item, so the arrow keys stay within the items; Tab reaches it. It closes the sheet and focus returns to the button, as do Escape, a swipe down and a tap beside the sheet. The label comes from the cancel label of provideCkui(). A narrow window with a mouse keeps the popover.

Accessibility

  • The button keeps being a native <button> and gets aria-haspopup="menu", aria-expanded and, while the menu is open, aria-controls. Values you set yourself on those attributes are given back as soon as the library no longer needs them (aria-controls when the menu closes, all of them when the button is destroyed). The menu is role="menu" with aria-orientation="vertical", named by the button (aria-labelledby); a button without an id gets one for as long as the menu is open, and an id you set is never replaced.
  • Items are role="menuitem" with a roving tabindex: focus is on the item, one item is the tab stop, and Tab never walks through the list. A disabled item is aria-disabled="true" and stays in the order, as the APG advises.
  • The focused item has a fill and a bar at the inline start, never colour alone; the bar shows for keyboard focus. In forced-colors mode the focused item is Highlight on HighlightText, other items and the danger item are CanvasText, disabled items are GrayText and the popover has a CanvasText border. A danger item is therefore only told apart by its colour outside forced colors: let its text or its icon say what it does ("Delete").
  • Nothing moves under reduced motion: the menu appears and disappears without an animation.
  • The popover is not modal: no focus trap, no inert page. It closes on Escape, an outside press, focus moving elsewhere, Tab and the button leaving view. On a phone it is modal like a dialog. A menu in a dialog closes alone on the first Escape.
  • Long labels wrap. The popover is at least 12rem wide, at most 30rem, and scrolls when the page is too short.
  • Global element styles. The items and the Cancel row are plain <button> elements styled by classes in a layer. An unlayered reset such as button { padding: 0; border: 0 } beats them: the rows lose their padding and their height. Keep those rules off the menu or put resets in a layer declared before ckui. The first rule below really breaks the menu; the rest scope it.
