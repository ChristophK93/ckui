Select

ck-select picks one option from a list. It is a button that shows the selected option and opens a list under it, the WAI-ARIA "select-only combobox", and on a phone the list is a bottom sheet. It works with Reactive Forms, ngModel and Signal Forms, and sits in a ck-field like a text input. Import CK_SELECT_IMPORTS from @ckui/core/select: it holds CkSelect, CkOption, CkOptgroup and CkSelectValue.

Examples

In a field

The usual place: a ck-field draws the box, the floating label, the hint and the error, and the select is its control. The label names the button, the placeholder lifts the label, and the field's size applies unless the select has its own. The options are the content of ck-select; ck-option takes a value and can be disabled.

On its own

Without a field the button has its own border and fill. It needs a name: give ck-select an aria-label or aria-labelledby, which move onto the button, or wrap it in a <label>. Development builds warn without one. The name also titles the sheet on a phone. The button is as wide as its container and the list is at least as wide as the button.

Rich options

What is inside ck-option is the row of the list, so it can hold a second line or a badge. On the button the option shows as its text, with a space between neighbouring elements (<b>A</b><i>B</i> reads "A B") and without aria-hidden parts. To draw it differently there, add an <ng-template ckSelectValue let-option>: option.value and option.text are those of the selected option, and the template only shows while one is selected.

Filter

filter adds a search field at the top of the list, and focus moves into it when the list opens. Typing keeps the options that contain the text, ignoring case and accents ("turk" finds Türkiye); a group without a match hides, and no match at all shows a "No results" row. The highlight jumps to the first match, and the keys of the open list work from the field. A polite announcement gives the number of results half a second after you stop typing, never when the list opens. The text clears when the list closes and focus returns to the button.

Disabled

A disabled option stays in the list, greyed out; it cannot be picked and the keys skip it. A disabled select, or one in a <fieldset disabled>, does not open and looks disabled; a list that is open closes when its select becomes disabled.

Sizes

The size follows the field, else provideCkui(), unless you set it. The button has the control height of the size, so it lines up with a button or an input of the same size. Under a coarse pointer sm and md are 44px; xl is 60px.

On a phone

When the list opens on a narrow viewport with a coarse pointer (the viewport is read at that moment), it is a bottom sheet instead of a popover: a dialog named after the select, with the name as its visible title, then the search field if there is one (a sheet with a filter is as tall as the screen allows and keeps that height while you type, so the field stays above the keyboard), then the options as full-width rows of at least 44px (60px at xl), each with a check mark when selected. Focus moves into the list, or into the search field; the same keys work; picking an option, Escape, a swipe down or a tap beside the sheet closes it, and focus returns to the button. A narrow window with a mouse keeps the popover.

Accessibility

  • The button is a native <button type="button"> with role="combobox", aria-haspopup="listbox", aria-expanded, and while the list is open aria-controls and, as long as the button holds the focus, aria-activedescendant. Being a button it can be labelled by a <label for> (a ck-field does that), disabled natively and disabled by a <fieldset>. The list is role="listbox" with role="option" children (aria-selected, aria-disabled) and role="group" groups named by their title.
  • Focus stays on the button while the popover is open: pressing an option or the padding of the list does not blur it, and the arrow keys move a highlight whose id is in aria-activedescendant. With a filter, focus moves into the search field, which has role="combobox", aria-autocomplete="list" and the highlight in aria-activedescendant; it is named after the select, with "Search". In the sheet the list itself takes focus and does the same.
  • The highlighted option has a fill and a bar at the inline start, never colour alone; the selected one has a check mark, a heavier weight and its own fill. In forced-colors mode the highlight is Highlight on HighlightText, the check mark is CanvasText, disabled options are GrayText and the list has a CanvasText border.
  • The result count of a filter is announced politely, half a second after typing stops. A value that no option has shows the placeholder, and a screen reader hears the placeholder, not a stale value.
  • Under reduced motion the chevron does not turn. Long option text wraps in the list; the button cuts it with an ellipsis.
  • The list is a popover with no focus trap or inert background, closed by Escape, a press outside it, focus moving elsewhere and the button leaving view; each closes it without a change. The sheet is modal, like a dialog.
  • Global element styles. The button and the options are plain elements styled by classes in a layer. An unlayered reset such as button { border: 0 } or ck-option { padding: 0 } beats them: the button loses its border and fill and the rows their padding. Keep those rules off the select (button:not(.ck-select__trigger)) or put resets in a layer declared before ckui. The first rule below really breaks the select; the rest scope it.
