Slider

ck-slider picks one number in a range by dragging a thumb, tapping the track or using the arrow keys. It works with Reactive Forms, ngModel and Signal Forms. Import CkSlider from @ckui/core/slider.

Examples

Basics

The value is a number or null and works two-way with [(value)], from 0 to 100 in steps of 1 unless you set min, max and step. The thumb has the slider role, so it needs a name: give ck-slider an aria-label or aria-labelledby. They move onto the thumb, and so does aria-describedby for a hint or an error. A wrapping <label> cannot name it. showValue draws the value next to the track.

Live value and commit

The value is written while the thumb moves: every pointer move and every key step. That keeps a form, a chart or a label in step, but it is too often for work such as sending a target to a device. (valueCommit) fires once when a change by the user ends, with the new value: on release after a drag or a tap on the track, and for the keyboard when the key is released, so a held arrow key is one commit and not one per repeat. It also fires when focus leaves while a key is still down. It does not fire when the value ends where it started, and never for a value that the form or [value] writes. A touch that the browser takes for a vertical scroll is cancelled: the value goes back and nothing is committed.

(valueChange), in contrast, reports every write to the value, one from a form included.

One control, three form APIs

The same control three times. A programmatic write (setValue, a model change, reset) moves the thumb and never counts as a change by the user: only a pointer or a key does, and the form is dirty only then. With Signal Forms the limits are set in the schema (min(path.grade, -10)), and the field passes them to the slider; binding [min] next to [formField] is an error.

Sizes

The size follows provideCkui() unless you set it. The height is the control height of the size, so the slider lines up with a button or an input of the same size, and all of it is the hit area of the track. Under a coarse pointer sm and md are 44px; xl is 60px, for one-thumb use on a bike. The thumb is drawn at 1, 1.25, 1.5 and 1.75rem, with a hit area of at least 44px on a coarse pointer whatever its size.

Unit and decimals

unit follows the value in its text, so a screen reader says "4.5%". A step with decimals, such as 0.5, shows that many digits and counts without drift: 0.1 + 0.2 is 0.3, never 0.30000000000000004. Steps are counted from min. Numbers are formatted with the locale of the app (LOCALE_ID).

Value text

valueText writes the text yourself, for a value that is better said in words. It is used for aria-valuetext and for showValue, and is called with the shown value. 

{{ samples.text }}

Values from outside the range

A value from a form that is above max, below min or off the step is shown clamped to the range and snapped to the step, and is not written back: the form stays pristine and holds what it was given. Only a pointer or a key writes. No value shows the thumb at min with an empty fill; a screen reader hears min. A min above max is a mistake that counts as max = min. 

{{ samples.outside }}

Disabled

A disabled slider leaves the tab order and ignores the pointer and the keys. A slider inside a <fieldset disabled> does the same and looks disabled; it is marked aria-disabled when the page loads and again when it takes focus, because a fieldset has no way to tell a custom element that it changed.

Accessibility

  • The thumb follows the WAI-ARIA slider pattern: role="slider" with aria-valuenow, aria-valuemin, aria-valuemax, aria-valuetext (the value with its unit, or what valueText returns) and aria-orientation="horizontal". It is a custom element rather than input type="range", so it looks and behaves the same in every browser and its hit area is not tied to what is drawn. It needs a name; development builds warn without one. With no value aria-valuenow is min.
  • The pointer works on the track and the thumb, with the pointer captured so a drag can leave the control. A press focuses the thumb, so the keys work right after. Only the primary button of the primary pointer counts. On a touch screen the value moves with the first horizontal move or when the finger lifts, so a vertical swipe that starts on the track still scrolls the page (touch-action: pan-y).
  • The whole height of the control is the hit area of the track: 32 to 60px, and at least 44px on a coarse pointer. The thumb has its own hit area of at least 24px, 44px on a coarse pointer, also where it is drawn at 16px, and the track is inset so that hit area never leaves the control.
  • In right-to-left text the track runs from the right: min is at the inline start, Left and Right swap, and a press is measured from the right. The direction comes from the dir attribute.
  • The focus ring is drawn around the thumb for keyboard focus. In forced-colors mode the rail has a CanvasText border, the fill is Highlight, the thumb is Canvas with a ButtonText border, a disabled slider is GrayText and the ring is Highlight. Under reduced motion the thumb does not scale while it is pressed.
  • A change is not announced beyond what the slider already reports. When another part of the page depends on the value, say what changed yourself.
  • Global element styles. The parts are plain spans, and the rail and the thumb each draw their ring with a border. An unlayered reset such as * { border: 0 } beats the layered control and removes both. The thumb and the rail are placed without margin or padding, so a reset of those does not move them. A global :focus-visible { outline: … } draws over the focus ring as well. Keep those rules off the slider (:not(.ck-slider__thumb)) or put resets in a layer declared before ckui. The first rule below really breaks the slider; the rest scope it.
