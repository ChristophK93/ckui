Dialog

A dialog asks the user for something before the page goes on: a confirmation, a short form, a piece of help. It is modal: the page behind it is dimmed and inert, focus stays inside, and Escape closes it. On a phone it becomes a bottom sheet as tall as its content that can be swiped away. Open one with CkDialog from @ckui/core/dialog and a component or template, or declare a <ck-dialog> in a template.

Examples

Service: a component with data and a result

open() takes a component or a template and returns a CkDialogRef. The content injects its data with CK_DIALOG_DATA and the ref with CkDialogRef. ref.closed resolves after the dialog has left the screen, with the value passed to close() or [ckDialogClose], and with undefined when the dialog was dismissed.

Template: ck-dialog

<ck-dialog> declares the same dialog in a template. Its content is one <ng-template>, rendered only while open is true, so nothing in it exists while the dialog is closed. [(open)] follows the dialog back to false whenever it closes, and (closed) carries the result.

Confirm with an alertdialog

role: 'alertdialog' is for a message the user has to answer. Mark the least destructive action with ckDialogInitialFocus, so that Enter or Space right after the dialog opens never deletes anything. A dialog has no title bar of its own: put ckDialogTitle on a heading in the content, and the dialog is named by it.

A dialog that scrolls

When the content is taller than the screen, only ck-dialog-body scrolls. The title row and the actions stay in view. The body becomes a tab stop while it scrolls, so a keyboard user can reach all of it, and it is never the element that takes focus when the dialog opens.

Full height

A sheet is as tall as its content, up to the height of the screen. fullHeight makes it as tall as the screen allows, for a picker or a long form. The actions stay at the bottom. It changes nothing for a modal. 

{{ samples.fullHeight }}

Forced mode

mode: 'auto', the default, opens a sheet when the screen is narrow and the pointer is coarse, and a centred modal otherwise. It is decided once, when the dialog opens. Force modal or sheet when the content needs one shape.

Providers of the opener

A component opened through CkDialog sees the providers of the app root. For providers that live lower, such as route-level ones or those of the opening component, pass inject(Injector) from the opener as injector. CK_DIALOG_DATA and CkDialogRef are provided on top of it. A template keeps the injector of the place where it was declared.

Closing again does nothing: only the first close() counts. When the app is destroyed every open dialog is removed, the page behind it is live again and every closed resolves with undefined. On the server nothing is rendered. The <ck-dialog> inputs are read when the dialog opens; changing one while it is open has no effect. Do not confuse the <ck-dialog> element, which only declares the dialog and renders nothing itself, with the .ck-dialog class of the surface in the overlay. A dialog that has neither a ckDialogTitle nor an ariaLabel logs a warning in development.

Accessibility

  • The panel has role="dialog" or alertdialog and aria-modal="true". ckDialogTitle names it and ckDialogDescription describes it; without a title, set ariaLabel. The names follow the content: a title that appears later or goes away updates the panel.
  • Initial focus goes to the element with ckDialogInitialFocus. Without one it goes to the first tabbable element of the content, never the close button, which comes last in the tab order. A dialog with nothing to press focuses the panel itself, so focus does not stay on the page behind it.
  • Focus is trapped while the dialog is open and the page behind it is inert, so neither Tab nor a screen reader's virtual cursor leaves. When a dialog closes, focus returns to the element that opened it. When a second dialog closes, it goes to the dialog underneath. If the opener is gone and no dialog is underneath, focus ends up on the page body: move it yourself in your closed handler, or after ref.closed resolves, to a sensible place such as the list the opener belonged to.
  • Escape closes only the topmost dialog. A dialog with dismissible: false ignores Escape, the backdrop and the swipe; make sure it always has a button that closes it.
  • The close button is named by the close label, which can be translated through provideCkui({ labels }), and is at least 44px on a touch screen. On a sheet the swipe handle is decorative; every action it offers also exists as a button.
  • Toasts stay above dialogs and clickable. A dialog opened from a toast's action takes focus, and the toast that held focus closes without dropping it.
  • On a phone the actions stack at full width in reading order, the sheet keeps the safe-area inset of the screen below its content and the page behind cannot scroll. With prefers-reduced-motion the dialog neither scales nor slides. In forced-colors mode the panel has a visible border.
  • Global element styles. A reset such as h2 { margin: … }, p { margin: … } or button:focus-visible { outline: … } beats the layered dialog styles, and a rule that sets display on the host element of a dialog component stops its body from scrolling. Declare resets in a layer before ckui, or scope them with :not(.ck-dialog__title), :not(.ck-dialog__description) and :not(.ck-button).
  • The dialog lives in the overlay container, a child of body. Under a nested data-ck-theme it follows the theme of the page, not of the section that opened it.
