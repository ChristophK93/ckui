Field

ck-field wraps one native <input> or <textarea> marked with ckInput, and gives it a floating label, a hint, an error, and prefix and suffix content. It works with Reactive Forms, ngModel and Signal Forms. Import CK_FIELD_IMPORTS from @ckui/core/field. ck-hint and ck-error come from @ckui/core/form, which the field entry point re-exports.

A ck-stepper can be the control of a field instead of an input: the field draws the box, label, hint and error around it. So can a ck-select: its label floats once it has a value or a placeholder.

When errors show

A ck-error is hidden, even if you render it, until the control is invalid and touched, or its form was submitted. While it shows, the field draws a danger border, sets aria-invalid on the control and adds the error to aria-describedby. The hint stays visible next to it. All errors sit in one polite live region, so a newly shown error is announced once. Set invalid on the field to force the state by hand, for example for an error that comes from your server.

Label float

With labelFloat="auto" the label floats while the control is focused, has a value (typed, or written by Reactive Forms, ngModel, Signal Forms or [value]), has a placeholder, is autofilled, is a native date, time, datetime-local, month or week control, or when the field has a prefix. The notch behind the floated label is a gradient that is clear above the border and filled with the field colour below it, so it never shows a patch on a page colour that differs from the field.

Prefix and suffix

ckPrefix and ckSuffix hold text, an icon, or interactive content. A button stays in the tab order, after the control. Text is not added to the accessible name; point aria-describedby at it when it matters, as the amount does here. A field with a prefix always keeps its label floated.

Sizes

The size follows provideCkui() unless you set it. Under a coarse pointer sm and md are 44px high and the text is at least 16px, so a phone does not zoom in on focus; xl is 60px and stays 60px.

Disabled and read only

Disabled follows the control: the disabled attribute, a disabled form control, or a disabled <fieldset>. A read only control looks normal and stays focusable.

The field host gets the classes ck-field, ck-field--{size}, and ck-field--floated, ck-field--invalid, ck-field--disabled or ck-field--textarea while those apply. A required control (the required attribute, Validators.required or Signal Forms required()) gets an aria-hidden asterisk in its label.

Keyboard

Keys in a field
Key Action
Tab Moves to the control, then to interactive prefix and suffix content such as a button, in that order. Shift+Tab goes back.
Enter In an input, submits the form as the browser does. In a textarea, inserts a new line.
Any other key Is the native input's own behaviour. The field adds no keys.

Accessibility

  • The control is a native <input> or <textarea>. The field sets the label's for and gives the control an id (an id you set stays), so the label is its accessible name wherever it floats.
  • aria-describedby lists the ck-hint ids, plus the ck-error ids while errors show. Tokens you put there yourself are kept, and follow your own bindings.
  • aria-invalid="true" is set while errors show; a value you set is restored after. A required control gets aria-required="true" unless it is natively required.
  • Errors sit in one aria-live="polite" container that exists from the start, so a newly shown error is announced once.
  • The label is cut with an ellipsis when it is too long, but the full text stays in the page, so the accessible name is never shortened.
  • The focus ring is an outline on the whole box while the control has keyboard or text focus, in forced-colors mode too. The label and notch use system colours in forced-colors mode, and the float is instant under prefers-reduced-motion.
  • Under a coarse pointer the control is at least 44px high and its text at least 16px. Autofilled values float the label through the :autofill pseudo-class.
  • Global element styles. Your own unlayered rules such as input { font: … } or :focus-visible { outline: … } beat the layered field, by design. This site's own :focus-visible rule is why the demos reset the outline on .ck-field .ck-input. Put resets in a layer declared before ckui.
  • Template linting. angular-eslint's label-has-associated-control flags <ck-field><label>…</label><input ckInput>, because the link is made at runtime. Either write for and id yourself (the field keeps both), or turn the rule off for templates that use ck-field.
  • Development builds warn about a field without a <label>, a field without exactly one ckInput, a ck-error outside a field, and a standalone input without an accessible name.
