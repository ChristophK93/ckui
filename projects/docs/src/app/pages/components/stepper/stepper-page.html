Stepper

ck-stepper changes a number with one thumb: a minus button, the value and a plus button. Tap a button, hold it to repeat, type a number, or use the arrow keys. It works with Reactive Forms, ngModel and Signal Forms. Import CkStepper from @ckui/core/stepper.

Examples

Basics

The value is a number or null and works two-way with [(value)]. The input is a text field with the spinbutton role, so it needs a name: give ck-stepper an aria-label or aria-labelledby (they move onto the input, and so does aria-describedby for a hint or an error), or wrap it in a <label>. A button press steps once; hold it and it repeats after 400 ms, every 80 ms, and five steps at a time after two seconds.

One control, three form APIs

The same control three times. A programmatic write (setValue, a model change, reset) reformats the field and never counts as a change by the user; only typing, a button or a key does, and each step is one change. With Signal Forms the limits are set in the schema (min(path.ftp, 50)), and the field passes them to the stepper; binding [min] next to [formField] is an error.

Sizes

The size follows provideCkui() unless you set it. The height is the control height of the size, so the stepper lines up with a button or an input of the same size, and both buttons are squares of that height. Under a coarse pointer sm and md are 44px; xl is 60px, for one-thumb use on a bike.

Unit

unit is drawn after the value and is part of aria-valuetext, so a screen reader says "250 W". It is hidden from assistive technology itself, so it is not read twice.

Decimals

A step with decimals, such as 0.5, shows that many digits and counts without drift: 0.1 + 0.2 is 0.3, never 0.30000000000000004. Steps are counted from min, so a minimum of -2 with a step of 0.5 keeps the grid. Numbers are formatted with the locale of the app (LOCALE_ID), and typing accepts both . and , as the decimal mark.

Limits and typing

min and max clamp every way the value can change, and a button is disabled at its limit. Typed text is read on Enter or when focus leaves: the number is clamped and snapped to the step; text that is not a number goes back to the last value; an empty field is null, a valid value. From null the first arrow or button press starts at min, else at 0. While you type, the arrow keys step from the number you typed.

Accessibility

  • The value follows the WAI-ARIA spinbutton pattern: a text input with role="spinbutton", aria-valuenow, aria-valuemin and aria-valuemax (each only when it exists) and aria-valuetext with the unit. With no value there is no aria-valuenow. It needs a name; development builds warn without one.
  • The minus and plus buttons are outside the tab order, as in the pattern, so the stepper is one tab stop. Pressing one with a mouse or a pen keeps focus where it is and moves it to the value when it was elsewhere, so the arrow keys work right after. On a touch screen focus is left alone, so the on-screen keyboard does not open on every tap. A screen reader can still activate the buttons.
  • The buttons are squares of the control height: at least 44px on a coarse pointer, 60px at xl. A long press repeats and speeds up; moving the pointer off the button, a cancelled touch, the control being disabled or reaching a limit stops it. The context menu of a long press on Android is suppressed on the buttons.
  • The numbers use tabular figures, so the control keeps its width while the value changes. inputmode="decimal" brings up a number keypad. That keypad has no minus sign on some phones, so a stepper with a negative min uses inputmode="text" instead.
  • One focus ring is drawn around the whole control while the value has focus; as in any text field that is every kind of focus, a tap on a button included. In forced-colors mode the control has a ButtonText outline and the ring is Highlight.
  • In right-to-left text the minus button stays at the inline start, which is the right edge. The direction comes from the dir attribute.
  • A change is not announced beyond what the spinbutton already reports. When another part of the page depends on the value, say what changed yourself.
  • Global element styles. The parts are a plain button and input. An unlayered rule such as button { border: … } beats the layered control, and a global :focus-visible { outline: … } draws a second ring on the input. Keep those rules off the stepper (:not(.ck-stepper__button)) or put resets in a layer declared before ckui. The first rule below really breaks the buttons; the rest scope it.
