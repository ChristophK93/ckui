Button

ckButton styles a native <button> or <a>. There is no <ck-button> element, so type, form, aria-* and routerLink stay on the real element. Import CkButton from @ckui/core/button.

Examples

Variants

Primary and danger are filled, secondary has a control fill and border, ghost has neither. Pick one primary button per view.

Hover and pressed fills are translucent overlays, so they show on the page, on a surface and on a raised surface alike:

Sizes

The size follows provideCkui() unless you set it. Under a coarse pointer sm and md are 44px high; xl is 60px and stays 60px. 

{{ samples.sizes }}

Icons

Any projected <svg> or icon component that wraps one is sized to 1em and takes the text colour. An icon-only button is square and must be named. 

{{ samples.icons }}

Loading

A loading button keeps its width and its name, stays focusable and ignores clicks, so a double submit cannot happen. The demo toggles it by hand; in your app, bind it to the pending request. 

{{ samples.loading }}

Links

On an anchor, routerLink and href work as usual. A disabled link is removed from the tab order and its click is blocked.

The host gets the classes ck-button, ck-button--{variant}, ck-button--{size}, and ck-button--icon-only, ck-button--loading or ck-button--disabled while those are on. A label that is too long for its container wraps instead of overflowing.

Keyboard

Keys on a button
Key Action
Enter, Space Activates a button.
Enter Follows a link button. Space does nothing on a link, as with any link.
Tab Moves focus to the button. A disabled button and a disabled link are skipped; a loading one is reachable but does nothing.

Accessibility

  • It is the native element, so role, name, form behaviour and keys come from the browser.
  • A loading button gets aria-disabled="true". The label stays in the page, faded, so the accessible name does not change, and the spinner is hidden from assistive technology. A polite live region announces the loading label once when loading starts, and nothing when it ends.
  • Focus is never moved when loading turns on or off, so a keyboard user stays where they were.
  • The focus ring is an outline on :focus-visible. Every variant has a transparent 1px border, which becomes visible in forced-colors mode. The spinner stops turning under prefers-reduced-motion.
  • Hover styles apply only on devices that can hover.
  • Global element styles. Your own unlayered rules such as a { color: … } or a:hover { text-decoration: … } beat the layered button, by design. Scope them with a:not(.ck-button), or put resets in a layer declared before ckui: @layer reset, ckui;.
  • Text and borders meet WCAG 2.2 AA contrast in both themes. Heights follow --ck-control-height-*, so touch targets are at least 44px under a coarse pointer.
