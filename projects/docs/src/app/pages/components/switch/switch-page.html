Switch

ck-switch turns one setting on or off, and takes effect at once: auto-upload, audio cues, developer tools. It is a native checkbox with the switch role under a label, so the whole row is the tap target. It works with Reactive Forms, ngModel and Signal Forms. Import CK_SWITCH_IMPORTS (the switch and its hint) from @ckui/core/switch.

Examples

Basics

The value is a boolean and works two-way with [(value)]. The text inside ck-switch is the label: it names the switch, and a click anywhere on the row toggles it. Use a switch for a setting that applies immediately; for a choice that is saved with a form, a checkbox says that better.

Hint

ck-switch-hint adds a line of help under the label. It describes the switch (a screen reader reads it after the name) and is part of the row, so a click on it toggles too.

Label position

By default the text comes first and the switch sits at the end of the row, as in a settings list. labelPosition="end" puts the switch first. In right-to-left text both flip, and the thumb moves to the other side.

One control, three form APIs

The same control three times. A programmatic write (setValue, a model change, reset) moves the thumb and never counts as a change by the user; only a click or Space does. null from a form counts as off. The control is touched when focus leaves it.

Sizes

The size follows provideCkui() unless you set it. The track grows from 2.25 × 1.25rem to 4 × 2.25rem, and the row is never lower than the control height of its size, so it is 44px or more on a coarse pointer and 60px at xl, for one-thumb use on a bike.

A disabled switch is blocked, greyed and skipped by Tab, and it keeps showing its state by the thumb position. A <fieldset disabled> around switches does the same without any input.

Accessibility

  • It follows the WAI-ARIA switch pattern: a native checkbox with role="switch", so the checked state is native and a screen reader says "on" or "off". The text names it and a ck-switch-hint describes it; the name does not repeat the hint.
  • The state is never colour alone: the thumb sits at the start of the track when off and at the end when on, and moves to the other side in right-to-left text. The on track is at least 3:1 from the off track, and each thumb is at least 3:1 from its track, in both shipped themes.
  • The row is the tap target: at least the control height of the size, so 44px or more on a coarse pointer and 60px at xl. A long label wraps in its own block and never pushes the switch out of the row.
  • The focus ring is drawn around the track for keyboard focus only. In forced-colors mode the track border and the thumb are CanvasText, the on track is Highlight with a HighlightText thumb, and a disabled switch is GrayText.
  • The thumb moves over --ck-duration-normal, and not at all under prefers-reduced-motion.
  • A switch applies immediately, so there is nothing to announce beyond the state change the screen reader already reports. When another part of the page depends on it, say what changed yourself.
  • Global element styles. The parts are a plain label and input. An unlayered rule such as input { border: … } beats the layered control. Keep those rules off the switch (input:not(.ck-switch__input)) or put resets in a layer declared before ckui. The first rule below really breaks the switch; the rest scope it.
