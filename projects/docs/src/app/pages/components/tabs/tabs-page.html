Tabs

ck-tabs switches between views on the same page: a row of underlined tabs and the panel of the selected one, such as Predefined, Mine and Shared. It follows the WAI-ARIA tabs pattern. It is not a form control and not navigation between pages. Import CK_TABS_IMPORTS from @ckui/core/tabs.

Examples

One panel for every tab

Each ck-tab has a value; the group's value is the one of the selected tab and works two-way with [(value)]. A ck-tab-panel without a value is shared: it stays in place and you show the content of the selected tab in it, like one list that follows the source. Give the row an aria-label: a tab list needs a name.

The model starts as null and the first tab is shown. That default is only reflected: the model stays null until the user picks a tab, and a click on the tab that is already shown writes its value. A panel for each tab

Give a panel the value of its tab and it is hidden unless that tab is selected. Every tab points at its own panel with aria-controls, and each panel is labelled by its tab. A panel whose value matches no tab is never shown, and development builds warn about it. Add value="audio" to the group to start on a tab.

A panel that starts with buttons

A panel is a tab stop (tabindex="0") by default, so a keyboard user can reach and scroll its content. The WAI-ARIA pattern asks for that only while the content does not start with a focusable element. When it does, as in a list of buttons or links, Tab would stop on the panel and then on the first button. Set [tabStop]="false" and the panel has no tabindex at all: Tab goes from the selected tab straight to the first button. There is no automatic detection. Leave the default for text, a chart or anything else that is not focusable itself.

Lazy content

A panel's content normally stays in the DOM while it is hidden, so what the user typed is still there when they come back. Wrap it in <ng-template ckTabContent> and it is created only while the panel is shown and destroyed when the panel is hidden, which suits expensive content such as a chart. Type into both fields, switch tabs and come back. Lazy content in a shared panel lives on across tab switches: that panel stays shown, so its content is created once.

Manual activation

With activation="manual" the arrow keys only move focus, and Enter or Space selects the focused tab. Use it when showing a panel is slow or moves the page. The one tab stop stays on the selected tab while focus has moved on.

Sizes

The size follows provideCkui() unless you set it. Each tab is as tall as the control height of the size, so the row lines up with a button or an input of the same size. Under a coarse pointer sm and md are 44px high; xl is 60px.

Overflow

When the tabs do not fit, the row scrolls sideways, inside itself: the page never does. The selected tab is brought into view when it changes and when the row gets narrower, and so is the focused tab. Labels are never squeezed; a single label wider than the row is cut with an ellipsis. The scrollbar is hidden, because the tabs themselves are keyboard operable. The group below sits in a 328px container, the content width of a phone, and starts on Week 11.

Disabled

A disabled tab stays visible, cannot be selected and is skipped by the arrow keys. It sets aria-disabled, so assistive technology announces it as unavailable, and like any disabled control it is exempt from the contrast minimum. It has tabindex="-1", so focus never falls to the page when a focused tab becomes disabled.

Accessibility

  • The tabs follow the WAI-ARIA tabs pattern: role="tablist" on the row, role="tab" with aria-selected and aria-controls on each tab, role="tabpanel" with aria-labelledby and tabindex="0" on the panel. The row is one tab stop (a roving tabindex on the selected tab) and the arrow keys move between tabs. A shared panel is labelled by whichever tab is selected. Turn the panel's tab stop off with [tabStop]="false" when its content starts with a focusable element.
  • The row needs a name (aria-label or aria-labelledby). A tab is named by its text. Development builds warn when the row has no name.
  • The selected tab is not marked by colour alone: it has an underline, a heavier weight and the stronger text colour. The underline is at least 3:1 against the page in both shipped themes; a custom --ck-tabs-indicator has to keep that.
  • In forced-colors mode the underline is Highlight, the line under the row CanvasText and the selected text CanvasText. A hovered tab turns Highlight; a disabled one is GrayText.
  • Every tab is as tall as the control height (at least 44px on a coarse pointer, 60px at xl) and as wide as its label with padding.
  • The focus ring is drawn inside the tab (on a pseudo-element), on keyboard focus only, so the scrolling row can never cut it off. The panel gets the ring around itself when it is focused by keyboard.
  • In right-to-left text the tabs run right to left, the underline follows each tab, and ArrowLeft and ArrowRight swap. The direction comes from the dir attribute on the row or an ancestor, not from the CSS direction property.
  • The underline grows in over --ck-duration-fast and not at all under prefers-reduced-motion. It belongs to the selected tab, so server-rendered markup is right without script.
  • The weight changes when a tab is selected, so the labels can shift a little. Set --ck-tabs-font-weight to the selected weight to prevent it.
  • Global element styles. A global :focus-visible rule such as this site's beats the layered rules and draws a second ring on the tab itself, outside the row, where the scrolling row cuts it off; the demos here switch it off. A global ck-tab-panel { display: … } keeps hidden panels on screen. Scope the rule or put resets in a layer declared before ckui.
