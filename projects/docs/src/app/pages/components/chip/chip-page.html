Chip

ckChip turns a native button into a compact toggle: a pill that is on or off. It is for filters and options that stay on the page, such as choosing categories, not for actions. Chips sit in a ck-chip-group that wraps onto several rows. Import CK_CHIP_IMPORTS from @ckui/core/chip.

Examples

A multi-select filter

Bind each chip with [(selected)]. A click, Space or Enter toggles it, and a selected chip shows a check mark before its label, so the state is never colour alone.

Icon

Put ckChipIcon on an inline svg for a leading icon. It is decorative and hidden from assistive technology. While the chip is selected the check mark takes its place, so the chip does not get wider. 

{{ samples.icon }}

Sizes

sm is the default, 2rem high. md, lg and xl follow the control heights, up to 3.75rem. Under a coarse pointer sm and md grow to 2.75rem, so every chip is a touch target. 

{{ samples.sizes }}

Wrapping

The group is a flex row that wraps. --ck-chip-group-gap sets the space between chips and between rows; it falls back to --ck-space-2. 

{{ samples.wrapping }}

Disabled

disabled sets the native attribute. A disabled chip is out of the tab order, ignores clicks and keys, and keeps its check mark when it is selected. A chip inside <fieldset disabled> looks and behaves the same. 

{{ samples.disabled }}

Long text

A chip never grows past its row. Text that does not fit is cut with an ellipsis while the check mark and the icon keep their size. Screen readers still read the full text. 

{{ samples.truncation }}

Changing chips from code

Setting selected in code only redraws the chip. It never emits selectedChange, so resetting a filter does not run your change handlers.

The chip gets the classes ck-chip, ck-chip--{size}, ck-chip--selected and ck-chip--disabled. Its text lives in ck-chip__label, a block of its own, so inline markup inside the text keeps its spaces. Chips are not removable and are not a listbox: each is an independent toggle.

Keyboard

A chip is a native button, so the browser handles its keys. Every chip is in the tab order; there is no arrow-key roving.

Accessibility

  • Toggle button. A chip follows the WAI-ARIA toggle button pattern: a native button with aria-pressed set to true or false. Screen readers say "toggle button, pressed". The chip owns aria-pressed; do not set it yourself.
  • Never colour alone. A selected chip shows a check mark before the label, and its fill stays 3:1 or better from an unselected chip in both shipped themes. The check is hidden from assistive technology.
  • Name the chip and the group. A chip needs text, an aria-label or an aria-labelledby. A ck-chip-group needs an aria-label or aria-labelledby. Development builds warn when either is missing.
  • Target size is 2rem at sm and 2.75rem under a coarse pointer, 3.75rem at xl; the space between chips keeps neighbouring targets apart.
  • In forced-colors mode a selected chip is drawn in the system highlight colours, and the check mark stays. The focus ring and the disabled look follow the same rules as the button. Under reduced motion the fill changes without a transition.
  • In right-to-left text the check and the icon move to the right of the label with the rest of the content.
  • Global element styles. The chip is a button with an svg inside. An unlayered rule such as button { border: 0; background: none } (the chip loses its fill and border) or svg { inline-size: 100% } (the icon fills the chip) beats the layered chip. Scope such rules away from the chip or declare resets in a layer before ckui.
