Progress

ck-progress is a thin horizontal bar that shows how far some work is: a workout, an upload, a connection attempt. It is a progress bar for assistive technology, and the app writes its own text next to it: there is no label and no percentage inside. Import CkProgress from @ckui/core/progress.

Examples

Determinate

value is a number from 0 to max (100 by default). The bar always needs a name: give it an aria-label or point aria-labelledby at visible text. Values outside the range are clamped, which these buttons let you try.

Indeterminate

null means the work has no known end. A segment slides along the track; the bar has no aria-valuenow. Under reduced motion nothing moves: the bar is half full and still.

Value text

A percentage says little about "step 2 of 7". valueText becomes aria-valuetext and replaces what assistive technology reads. Set max to the number of steps.

Naming

A progress bar without a name is announced as just "progress bar". Use an aria-label, or aria-labelledby when the page already has the words. Development builds warn when there is neither.

The host is role="progressbar" with aria-valuemin="0", aria-valuemax and, while determinate, aria-valuenow. It gets the class ck-progress, and ck-progress--indeterminate while the value is null. The fill is the ck-progress__fill element, scaled with a transform so that it grows from the start edge in left-to-right and right-to-left text.

Keyboard

A progress bar is not interactive: it is not in the tab order and takes no keys. For a value the user sets, use a slider instead.

Accessibility

  • The bar follows the WAI-ARIA progressbar pattern. It needs a name, and development builds warn without one. An indeterminate bar has no aria-valuenow, which is how assistive technology tells "busy" from "50%".
  • Not a live region. Assistive technology does not announce value changes by itself. Say the milestones that matter ("Upload complete") in a role="status" element or a toast, not on every tick.
  • The fill is at least 3:1 against the track in both shipped themes, since the bar is a graphic that carries the value. Check the same ratio when you set --ck-progress-fill or --ck-progress-track.
  • The fill grows over --ck-duration-normal when the value changes, and not at all under prefers-reduced-motion. The indeterminate slide is replaced by a still, half-width fill.
  • In forced-colors mode the track gets a CanvasText outline and the fill is drawn in Highlight.
  • In right-to-left text the fill grows from the right and the indeterminate segment slides from right to left. The direction comes from the dir attribute.
  • Global element styles. The fill is a span. An unlayered rule such as span { position: static } (the fill leaves the track) beats the layered bar. Scope such rules away from it or declare resets in a layer before ckui.
