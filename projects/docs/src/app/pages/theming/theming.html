Theming

ckui ships one stylesheet. It declares custom properties and a few .ck-* classes, nothing more, so it never restyles your page by itself.

Set up

To use the library's font, text colour, background and color-scheme for the whole page, add the class ck-root to <html> (not <body>: its color-scheme would not reach the viewport and scrollbars). Without it your page keeps its own look and only the components use the tokens. 

{{ samples.rootClass }}

Light and dark

The light theme is the default and the dark theme follows prefers-color-scheme. Force one with data-ck-theme="light" or data-ck-theme="dark" on any element: the whole page or a single section. Themes nest, and a nested section recomputes every theme token and sets its color-scheme. It does not repaint by itself: text colour and background are inherited from the surrounding page, so a section that should look different also needs the class ck-root (or its own color and background from the tokens). The theme switcher in the header of this site sets the attribute on <html>. 

{{ samples.forceTheme }}

Three layers of tokens

  1. Primitive: raw values such as --ck-indigo-600, --ck-space-4 or --ck-radius-md.
  2. Semantic: meaning built on the primitives, such as --ck-color-primary or --ck-color-surface. Colours change with the theme.
  3. Component: per-component knobs such as --ck-button-radius. The library never declares these. Each component reads its own with a fallback to a semantic or primitive token, so setting one anywhere in your CSS changes only that component, and nested themes keep working.

The full list with live values is on the token reference.

Why your CSS wins

Every rule in the library sits in one cascade layer, @layer ckui. Any CSS you write outside a layer beats it regardless of selector specificity or source order, so you never need !important or deeper selectors to restyle a component. 

{{ samples.layerWins }}

Touch and motion

  • Coarse pointer ((pointer: coarse)): the sm and md control heights become 2.75rem (44px), control font sizes become at least 1rem so iOS does not zoom into inputs, and --ck-target-min grows from 1.5rem to 2.75rem. Use --ck-target-min for your own tap targets.
  • Reduced motion (prefers-reduced-motion: reduce): every --ck-duration-* becomes 0ms. Use the duration tokens for your own transitions and they follow along.

Configuration with provideCkui

provideCkui() sets app-wide defaults. All options are optional and invalid values throw a TypeError when provideCkui() is called for size and sheetBreakpoint. A labels factory that does not return a signal throws when the labels are first read. 

{{ samples.provideCkui }}
  • size: 'sm', 'md' or 'lg', the size a component uses when its own size input is unset. Default 'md'.
  • sheetBreakpoint: a finite number of px above 0. A coarse pointer on a viewport narrower than this shows overlays as bottom sheets instead of popovers. CSS cannot use a custom property in a media query, so this is configuration, not a token. Default 640.
  • labels: the built-in strings, see below.

Labels

Built-in strings (a close button's name, a loading message) come from a signal injected as CK_LABELS. Pass only the keys you want to change: missing, blank or non-string values fall back to the English default and unknown keys are ignored. Every component package adds its own keys, which is not a breaking change because you pass a partial object. Current defaults:

@for (label of defaultLabels; track label[0]) {
{{ label[0] }}
{{ label[1] }}
}

labels accepts a partial object (fixed), a signal of one (changes at runtime), or a factory that returns such a signal. Here is a signal: 

{{ samples.labelsSignal }}

The factory runs in an injection context, which fits any i18n library: inject its service and return a computed that re-reads the translations when the language changes. ckui does not depend on a particular library.
